## Overview of the app structure

This project is a small React task manager. Its main idea is simple:

- the user adds, edits, completes, and deletes tasks,
- tasks are stored in browser local storage so they remain after refresh,
- the app shows a dashboard summary and a task list view.

The main logic is split across the files in src, especially components, hooks, pages, and utils.

---

## 1) Root app logic in App.jsx

This is the main controller of the app.

What it does:

- creates the central `tasks` state using the custom hook from useLocalStorage.js
- keeps track of:
  - `activeFilter` for showing all/pending/completed/overdue tasks
  - `currentView` for switching between dashboard and task list
  - `isAddFormOpen` for opening the add-task modal
- provides handlers like:
  - `handleAddTask` to insert a new task
  - `handleToggleComplete` to mark a task done or undone
  - `handleDeleteTask` to remove a task
  - `handleEditTask` to update a task

It also manages reminders with `setupReminder()` and a `useEffect` hook to request browser notification permission.

In short, App.jsx is the “brain” of the application.

## 2) Components in components

### a) AddTaskForm.jsx

This component is the modal form used to create a new task.

Key points:

- It uses local state called `formData` to store values typed by the user.
- The form collects:
  - title
  - description
  - priority
  - due date
  - reminder time
- When the user submits:
  - it checks that the title is not empty,
  - creates a new task object with:
    - an ID generated by `generateId()`
    - `completed: false`
    - `createdAt` timestamp
  - calls `onAddTask(newTask)` to send it upward to the main app
- After adding, it resets the form and closes the modal.

This is a classic controlled form in React.

### b) Sidebar.jsx

This is the left navigation panel.

What it does:

- renders the menu items for:
  - Dashboard
  - All Tasks
  - Pending
  - Completed
  - Overdue
- highlights the currently selected menu item
- shows counts for each category using `taskCounts`

The component is mostly presentational, but it also sends the selected filter upward through `onFilterChange`.

### c) TaskItem.jsx

This file represents one task card.

It handles three main states:

- normal view
- edit mode

In normal view, it shows:

- the task title and description
- priority badge
- due date and reminder date
- checkbox to mark complete
- edit and delete buttons

In edit mode, it replaces the card with an inline editing form so the user can update the task’s details.

Important logic:

- `isOverDue` checks whether the task is late
- `priority` is derived from the utility function `getTaskPriority()`
- clicking the checkbox toggles `completed`
- clicking edit lets the user modify the task
- clicking delete removes it

### d) TaskList.jsx

This component is responsible for displaying the list of tasks.

It does three important things:

- filters tasks by the selected view
- searches tasks by title/description
- sorts tasks by latest, due date, priority, or name

It uses local state:

- `searchTerm` for typing into the search box
- `sortBy` for choosing the sort option

Then it renders the filtered and sorted tasks by mapping over them and displaying each one using `TaskItem`.

If no tasks match, it shows an empty-state message.

## 3) Custom hook in useLocalStorage.js

This is a reusable custom hook for saving data to browser storage.

Why it is useful:

- it lets the app remember tasks even after the browser is refreshed
- it avoids manually writing localStorage code in several places

What it does:

- reads from `localStorage` when the app starts
- stores updated values back into `localStorage`
- safely handles errors in case storage is unavailable

The hook returns:

- `storedValue` for the current data
- `setValue` to update it
- helper methods `setTitle` and `getTitle` for title-related storage

This makes the app feel more persistent and user-friendly.

## 4) Page component in Dashboard.jsx

This file builds the dashboard view.

It computes and shows:

- total tasks
- completed tasks
- pending tasks
- overdue tasks
- completion percentage

It uses `useEffect` to recalculate stats whenever the `tasks` array changes.

It also creates:

- `StatCard` for summary blocks
- `ProgressBar` for the completion progress display

Additionally, it calculates “upcoming tasks” in the next 7 days and displays them in a small list.

So the dashboard is a read-only summary page that turns raw task data into useful insights.

---

## 5) Shared helpers in index.js

This folder contains small reusable utility functions.

### `generateId()`

Creates a unique ID for each task.

### `formatDate()`

Turns a raw date string into a readable human-friendly format.

### `IsTaskOverdue()`

Checks whether a task’s due date is in the past.

### `getTaskPriority()`

Returns the badge style and label for low/medium/high priority.

### `filterTasks()`

Returns the correct tasks depending on the current filter:

- completed
- pending
- overdue
- all

### `sortTasks()`

Orders tasks based on the selected sort option.

These utilities keep the components cleaner and make the app more consistent.

---

## 6) How the pieces work together

The flow is:

1. The app loads tasks from local storage.
2. The user opens the add form and creates a task.
3. The task is passed upward to the main app.
4. The app updates the task list.
5. The list view, dashboard, and sidebar all react to the updated tasks.

So the app follows a common React pattern:

- parent component manages state
- child components display UI and call callbacks
